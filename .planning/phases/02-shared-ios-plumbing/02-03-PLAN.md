<objective>
BOOK-18: a realtime `booking.update` with status `rescheduled`, or any status the app does not know yet, is decoded and applied instead of dropped.

Purpose: `RealtimeService` decodes each socket event with `try?` and returns on failure, so one unknown status silently drops the whole event and the open screen goes stale. `rescheduled` is a documented socket value (backend `docs/SOCKET-CONTRACT.md`) that the enum lacks.

Output: `BookingStatus` gains `rescheduled` and `unknown` with a decode that never fails on a string; every exhaustive switch decides the two cases explicitly; the `ReloadGeneration` helper, first used on the expert Upcoming Bookings list so it keeps only the newest of overlapping refetches; tests. Plan 02-13 applies the helper to the three client screens that refetch on `booking.update`.
</objective>

<objective>
The navigation half of PUSH-01 and PUSH-03, and BOOK-15's routing row: every route the shells push is registered on the stack that receives it, each destination opens on the tab that owns it with a fresh stack (D-04), and one table maps category and sub-category to a destination for push taps and notifications-list rows alike. Plan 02-10 then feeds real push payloads into this table and adds the mode switch.

Purpose: CR-01 (device-reproduced 2026-11-08) was a pushed `HomeRoute` on a Bookings stack that only registers `BookingRoute`. Today the client Search and Bookings stacks and the expert Topics stack still do not register `HomeRoute`, and several cases push onto Explore or Dashboard without selecting that tab. A notifications-list booking row in client mode hits the warning page now.

Output: one `homeStack` helper per shell, `HomeNavigationPath.replace(with:)`, `HomeRoute.requestDecision`, two new `PushDestination` cases, the shared table, and table tests.
</objective>

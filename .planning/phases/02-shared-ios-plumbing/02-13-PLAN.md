<objective>
BOOK-18 (client screens): overlapping refetches on Upcoming Booking details, Booking Summary and My Bookings keep only the newest response.

Purpose: each `booking.update` subscriber starts an unserialized refetch, so two events, or an event plus a pull-to-refresh, run overlapping fetches and the older response can land last, leaving the screen on stale state. Plan 02-03 built `ReloadGeneration` and gated the expert Upcoming Bookings list; this plan applies the same helper to the three client screens. It was split out of plan 02-03 to keep that plan within the file budget, and it runs in wave 3 because plan 02-05 edits the detail and summary view models in wave 2.

Output: three client view models whose fetch paths write data and load state only while their token is the newest.
</objective>

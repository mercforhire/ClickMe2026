# Phase 02 — UI Design Contract

> Visual and interaction contract for Phase 02: Shared iOS Plumbing. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this contract.** Phase 02 is a bug-fix phase on a live SwiftUI app. It changes rules, copy and wiring, not layouts. This file therefore does two things: (1) documents the design system exactly as the code has it today, and (2) locks the small set of UI deltas the 15 Phase 02 plans specify, including the ones Wave 1 already shipped. It introduces no new palette, no new spacing scale and no redesign. Where the shipped code departs from the 4-multiple spacing and 2-weight rules, the departure is listed as an inherited exception, not corrected here.
>
> **Why this exists now.** Wave 1 (plans 02-01, 02-03, 02-07, 02-09) is executed and committed. The execute-phase UI safety gate blocked Wave 2 because UI files changed with no UI-SPEC. Section "Wave 1 Shipped Decisions" records those decisions as the contract.

## Typography

All text uses `Font.brand(_ style:weight:)` (rounded, Dynamic Type) except where a view already calls `.system(.subheadline, design: .rounded)`, which maps to the same style. Sizes below are the default Content Size Category values. Line height is the system default for each text style; Phase 02 sets no explicit line height and no fixed font size (hero sizes of 34 pt and above are not used here).

| Role | Style / size | Weight | Line height | Phase 02 usage |
|------|--------------|--------|-------------|----------------|
| Label | `.caption` / 12 pt | Semibold (600) | system | Overtime banner text; "Retry" text button; day-of-week headers (inherited Medium) |
| Body | `.subheadline` / 15 pt | Regular (400) | system | Calendar day numerals, slot chip text, card time ranges |
| Heading | `.callout` / 16 pt | Semibold (600) | system | Month title in the calendar |
| Display | `.title3` / 20 pt | Regular (400) or Semibold (600) per element; section headers are inherited Bold | system | "Select a Time" section header |

Declared for new or changed text in this phase: **4 sizes** (12, 15, 16, 20) and **2 weights** (Regular 400, Semibold 600).

Inherited exceptions, unchanged: Bold (700) on Join button labels (`JOIN CALL`, `Join Call`, `Join Session`), on the selected calendar day and selected slot chip, and on the `title3` section header; Medium (500) on day-of-week headers. **Bold and Medium are inherited from shipped code and are not added by this phase.** No Phase 02 plan adds a weight, and new or changed text in Phase 02 uses only Regular or Semibold.

Inherited exception, size closeness: Body (15 pt) and Heading (16 pt) differ by 1 pt, so the month title is distinguished from calendar numerals by weight (Semibold vs Regular) and position, not by size. This is the existing calendar styling; Phase 02 does not change either size.

Dynamic Type: banner text carries `.fixedSize(horizontal: false, vertical: true)` so it wraps at large sizes instead of truncating. Any new text must use a text style, never a point size.

## Phase 02 UI Delta Contracts

### 1. Call lifetime and Ended state (02-01 shipped, 02-02)

| State | Trigger | UI |
|-------|---------|----|
| Live, before scheduled end | normal | No banner. Final-stretch banner in the last 5 minutes before end |
| Past scheduled end, before end + 55 min | `now > end` | Banner: `Scheduled time complete — you can wrap up when ready.` |
| Overtime warning | `now >= end + 55 min` and `< end + 60 min` | Same banner position and styling, text `This call will end in 5 minutes` |
| Auto-end | `now >= end + 60 min` | Ends via `CallCenter.endCall`; screen shows `Call Ended`, then dismisses as a normal hang-up does |
| Agora connection failed (02-02) | `AgoraConnectionState.failed` (raw 5) only | Maps to the local disconnected state; the view model runs the normal end path with reason `dropped`. The screen shows `Call Ended` and dismisses. No new copy and no new control |
| Agora disconnected (raw 1), connecting, reconnecting | initial state, post-`leaveChannel`, transient | No change. A user's own hang-up is never reported as a drop |

Banner geometry (unchanged): amber `hourglass` icon, `.caption` semibold text, 12 pt continuous corner radius, outer padding 24 horizontal and 12 top, enters with move-from-top plus opacity, `easeInOut` 0.25 s. The text change at end + 55 min animates with the same 0.25 s curve.

### 2. Join button visibility and states (02-04, 02-14)

The rule is `JoinWindow.isOpen`: open from start − 60 min through `max(end, start + 60 min)` inclusive; after that open until end + 60 min only when the server `can_join` is true; closed for any status other than `confirmed`, `in_progress`, `completed`. The result is a display gate; the server keeps the final say on `POST /join`.

| Surface | Button | Window open | Window closed | Not-joinable status (incl. `pending_reschedule`, `pending_approval`, `rescheduled`, `unknown`) |
|---------|--------|-------------|---------------|-----------------------------------------------------------------------------------------------|
| Client My Bookings card | `JOIN CALL`, 50 pt, 12 pt radius, accent fill with glow, `PressScaleButtonStyle` | Shown | **Hidden** (button removed, not dimmed) | Hidden. Awaiting-approval cards keep their existing placeholder |
| Client Explore today strip | `Join Call`, 50 pt, 14 pt radius, accent fill | Full accent, glow | **Dimmed**: accent at 55% opacity, no glow, disabled | **Not rendered** (02-14) |
| Expert Upcoming list | `Join Session` and the NOW badge | Shown | Hidden | Hidden |
| Expert dashboard strip | `Join Session` | Shown | **Dimmed and disabled**, existing styling unchanged | **Not rendered** (02-14, D-12) |

Live updates: the Join button on every surface above, and the expert NOW badge, re-evaluates inside `TimelineView(.periodic(from: .now, by: 60))`. The contract tolerance is therefore up to 60 seconds between a window edge and the UI flip. The edges themselves are inclusive to the second in `JoinWindow`; no surface may add its own window arithmetic. Only the two "starting now" pill helpers (`ExpertDashboardViewModel.isStartingNow`, `ExploreTodaysSessionsSection.isStartingNow`) keep their own arithmetic, by design.

Intentional behavior change to list in the Phase 02 UAT: Join disappears for `pending_reschedule` bookings on the Explore and expert dashboard strips (D-12).

Known limitation, state it in the UAT so it is not read as a defect: a client who drops during overtime can reconnect from the booking detail (Phase 3, CALL-03) but not from My Bookings, which has no `can_join`. Buttons on a push-opened or chat-opened booking detail (Join, Cancel, Reschedule, Leave Review, Book Again) may be inert until Phase 3 wires them.

### 4. Paid 6-day picker and reschedule (02-07 shipped, 02-08)

Accessibility (required, not recommended):

### 5. Push and notification navigation (02-09 shipped, 02-10)

No new visual. The contract is where a tap lands and that it never shows SwiftUI's unregistered-destination warning page (CR-01).

| Destination | Owning tab, client shell | Owning tab, expert shell |
|-------------|--------------------------|--------------------------|
| Booking detail (confirmations, reschedules, `payment_actions`), leave review | Bookings | Bookings |
| Booking summary (declines, cancellations, expirations, refunds) | Bookings | Bookings |
| Chat thread | Chats | Chats |
| Account security | Profile | Profile |
| Notifications list (unknown, empty or missing category; D-03 fallback) | Explore (the bell lives there) | Dashboard |
| Incoming-requests hub, single request (`RequestDecisionView`), payouts, KYC | not available in client mode (falls to the notifications list) | Dashboard |

Behavior contract:

1. Selecting the owning tab and replacing its stack happen together; Back returns to that tab's root.
2. Mode switch (02-10, D-02): when `target_role` differs from the current mode the app switches mode silently, with no confirmation, banner or toast, then routes. A missing `target_role` keeps the current mode.
3. D-03: a `target_role` of expert tapped in client mode, on an account without the expert role or without completed expert setup, stays in client mode and opens the notifications list. It is never forced into expert mode.
4. A tap that launches the app is held until the shell for its mode appears, then routed once. A tap while no account is signed in is dropped. The later of two taps wins.
5. Every `HomeRoute` is registered once per shell. Do not register it a second time on any tab (SwiftUI warns on duplicates).
6. Notification-list rows and push taps share the same destination table; a `booking/requests` row with a booking id opens that request, without an id it opens the hub.

### 6. Foreground push banner (02-11, CHAT-09)

No custom visual; this is system presentation. A foreground chat push (`route_category` message) whose `thread_id` equals the chat on screen presents with **no options** (no banner, no sound, no Notification Center entry). Every other thread, and every non-chat push, presents with banner, list, sound and badge. The notifications-list refresh still fires for every foreground push, suppressed or not. A chat with no thread id (preview seed) never suppresses.

### 7. Status badges for `rescheduled` and `unknown` (02-03 shipped)

See W1-4 to W1-7. In one line: never joinable, never a strip member, Booking Summary badge hidden, expert list keeps the row under Upcoming then Past-as-missed, and no neutral label.

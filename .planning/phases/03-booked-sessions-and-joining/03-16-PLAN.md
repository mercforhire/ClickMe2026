<objective>
Close gap G-03-3-WR01 (03-UAT test 3, code-review finding WR-01, user decision "fix both"): after the server accepts or declines an expert-proposed reschedule, the Accept/Decline card disappears even if the follow-up booking refetch fails.

Purpose: today both owners implement the responder's `refetch` as their silent `refresh()`, which swallows a failed detail GET and keeps the stale proposal. The user sees "Reschedule accepted" while the card still offers Accept New Time, and a second tap sends a second money-affecting POST. D-03 says the card disappears once Accept or Decline succeeds; this plan makes that true without depending on the refetch.

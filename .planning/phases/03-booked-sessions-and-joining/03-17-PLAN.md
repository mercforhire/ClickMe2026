<objective>
Close gap G-03-3-WR02 (03-UAT test 3, code-review finding WR-02, user decision "fix both"). The post-cancel toast must never promise a refund amount the server did not issue.

Purpose: today the refund case is chosen with the phone's clock, while the server applies the strict more-than-24-hours rule with its own clock. A phone clock running behind, a booking crossing the 24 h line between the last recompute and the server's handling, or the idempotent already-cancelled 200 all give `refund_amount: 0` while the client confirmed under `.chargedRefundable`. The toast then names the full amount as a refund in progress when none is coming. D-06 says the post-cancel message follows the server's answer. This plan makes the zero answer under that case neutral.

Output: the neutral `.chargedRefundable` zero arm in `CancelToastMessage`; updated and new Swift Testing rows, including the exact backend already-cancelled body; the UI-SPEC toast table row; WR-02 marked fixed in the review ledger; a device-checklist note.

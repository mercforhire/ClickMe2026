On a transient Stripe or network error the code re-throws, the row stays `scheduled` and stamped with no PaymentIntent, `longLeadChargeSweep` never selects it again, and `scaRecoveryWindowSweep` cancels the booking about six hours later, releasing the slot and notifying both parties with no charge ever attempted.

Purpose: a transient Stripe or database error at the T-24h profiles read or platform-card check never cancels a client's booking, either in the same run or through the 6-hour window, and nothing build 6 or Android reads changes. Transient errors after the stamp still can (T-04-45, follow-up todo), so this plan only partly closes 04-VERIFICATION truth 17 ("a transient Stripe error never cancels").

<assumptions>
- `assumption_delta_decision`: no-change.
- The two push handlers do not use the CallCenter alert (today's behavior): a push replayed during a call must not raise a "switch modes" alert on every foreground. They call `requestModeSwitch` directly with `source: .push`. `requestModeSwitch` itself refuses the switch during a call (plan 05-07), so the push path keeps the single-call invariant without the alert. The tap is held in `pushRouter.pending` and replayed when the call ends.
- Replaying the held tap the moment the call ends is safe: ending a call shows no post-call screen in the shell (see interfaces), so the switch it may make tears down nothing the user is looking at. Observing `CallCenter` in the shells follows the `CallOverlayHost` pattern. `CallCenter` publishes rarely (call start and end, minimize and expand), so the extra shell re-evaluations are negligible.
- `resolvePostAuthLanding` is not a user or push switch; it runs from Splash or the Login screen, outside a home shell, and gets no call check in this plan.
- A stored Expert mode for an account whose roles lack expert (possible on build 6, where Mode Switch let anyone pick Expert) is checked at launch: the user chose Expert mode earlier, so the lookup is the D-04 consent case, and an unfinished profile opens the hub instead of an empty dashboard.
- The foreground re-check and the `setupCheckPending` flag are plan 05-12, which depends on this plan.
- Edge probe (spec-less fallback): SIGN-06's row is `unclassified` and stays unresolved as a flagged assumption; the launch rules are written as truths and tested.
</assumptions>

<objective>
Close UAT gap G-05-1 (cosmetic): the setup hub's `Not now` button is hard to read on some iPhones.

Root cause (`.planning/debug/not-now-button-low-contrast.md`, confirmed by a simulator repro): `OverviewNotNowChrome` in `SignupOverviewView.swift` puts `Not now` in a leading toolbar item with a fixed dark-theme colour (`Brand.onSurfaceVariant`, #bacbbc), but the hub never pins its navigation bar's colour scheme. Every sibling signup screen and every Settings screen does pin it. The app has no app-wide dark opt-in, and the AppDelegate's opaque bar appearance colours only the bar's background, not its trait. On a phone in Light appearance with opaque glass (Reduce Transparency, and likely iOS 26.1 Liquid Glass "Tinted"), the iOS 26 toolbar capsule therefore renders light grey (#f2f2f2), giving 1.52:1 contrast. With the default Clear glass the capsule picks up the dark backdrop, which is why it looked fine in development.

Fix: pin the hub's bar dark with the same three modifiers its siblings use. The user kept UI-SPEC A1 (quiet secondary style) in UAT item 46, so the button itself does not change.

Purpose: a user sent to the setup hub can always see the way out.
Output: three modifiers in `SignupOverviewView.swift`, a device re-test step in checklist item 46, and a todo for the same latent pattern on the Availability settings screen.
</objective>

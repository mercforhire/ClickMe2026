<objective>
Close the save half of UAT gap G-05-6 (blocker): on a profile with an empty first or last name, every Profile Settings save fails with "Couldn't save changes / Please check the information you entered and try again."

Root cause (`.planning/debug/profile-settings-save-fails-incomplete-profile.md`, reproduced against the backend's real validation): both settings view models send one whole-form `PATCH /user/profile` on every debounced edit, and it always includes `basic.first_name` and `basic.last_name`, so an empty name goes out as `""` even when the user only edited State/Province. The backend schema has `min(1)` on both names and answers 422 VALIDATION_ERROR. Signup stores `''` for both names and no iOS setup step writes a last name, so this hits every iOS-created account (published experts included) until the user types a last name. This is a pre-existing defect, also present in App Store build 6.

This fix is iOS-only and does not need a backend deploy. Each save sends only the groups that changed (Android parity), a name key only when it is non-empty, and holds back a name the user cleared, exposing a required-field error for it. The visible error and the 422 field naming are plan 05-20. Backend and Android follow-ups are logged by plan 05-20, not done here.

Purpose: a user with an incomplete profile can save any edit, including clearing State/Province, without being blocked by a name they never set.
Output: `ProfileSettingsSnapshot` with pure tests, both view models moved onto it, and save-path tests against a mock of the backend's real 422.
</objective>

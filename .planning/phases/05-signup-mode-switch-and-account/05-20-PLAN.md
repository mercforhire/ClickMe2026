<objective>
Close the visible half of UAT gap G-05-6, and log the cross-repo follow-ups.

Plan 05-19 stopped the screen from sending empty names, so the save no longer fails on an incomplete profile. Two parts of the gap are left:
1. When a save does get a 422 (a name over 100 characters, an unknown language id, a future rule), the alert still shows only the backend's generic sentence, "Please check the information you entered and try again.", with no field named. `Error.userMessage` reads only the top-level message and ignores `errors[]`.
2. A user who clears a name they had set gets no feedback. Plan 05-19 holds that name back, but nothing on screen says why.

This plan names the fields from `errors[]` in iOS copy, through the existing `FieldValidationErrorResponse`, and shows a required-field error under a cleared name in `ValidatedField`'s error style. It also records the device re-test and the backend and Android follow-ups.

The backend stays out of the critical path. That is the planner's call, following the orchestrator's planning guidance for the live production backend, which serves App Store build 6. It is not a user decision. So root cause (2) of the debug session, the backend's `min(1)` on `basic.first_name` / `basic.last_name` contradicting `openapi/clickme-api.yaml` and signup's `''`, is a known residual pending a user decision. The new iOS build no longer sends empty names, so it does not depend on that fix. Whether to loosen `last_name` validation is an open product decision for the user. It is tracked in the backend todo (Task 3) and not decided here.

Requirement note: SET-01 is marked complete in ROADMAP.md and REQUIREMENTS.md (plan 05-09), and G-05-6 reopens it (see plan 05-19's objective and the Phase 5 notes in ROADMAP.md). SET-01 counts as closed again only when this plan and 05-19 pass and the G-05-6 re-test in checklist item 22 (Task 3) passes on a device.

Purpose: a failed profile save always says what to fix, and a held name is never silent.
Output: `Error.validationFieldErrors`, `ProfileSaveErrorMapper` with tests, both catch blocks on the mapper, `ProfileLabeledField(error:)` wired on both screens, checklist item 22's re-test, and two todos.
</objective>

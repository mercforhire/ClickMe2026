<objective>
Close the one gap left in Phase 5 verification (CR-01, VERIFICATION truth 16). Today, clearing the Skype / Zoom meeting link on Expert Settings is silently lost but reported as saved.

Root cause (05-VERIFICATION.md, 05-REVIEW.md CR-01): `makeExpertProfileUpdateBody()` maps an emptied link to a nil `meetingUrl`. The synthesized `Encodable` omits nil keys, so the request body is `{"professional_details":{}}`. The backend writes nothing for an empty group and still answers 200. `performAutoSave()` then sets `baselineMeetingUrl` to "", refreshes the expert profile and shows the checkmark, and the old link comes back on the next load. The code comment behind that rule predates BACK-04. Backend `df7fb18` ("allow experts to clear meeting_url (null or \"\")", Phase 1, on origin/main) makes `src/schemas/expertProfile.schema.js` accept "" and null, and `src/controllers/expert.controller.js` stores `meeting_url || null`. Production /health reported `28da165` at planning (2026-11-15), which contains `df7fb18`.

A second path keeps a cleared link on screen; the user folded it into this plan on 2026-11-15 (fix it, with a test, rather than log a deferral). `UserManager.refreshExpertProfile()` replaces `expertProfile` with the server response, so a link cleared on another device or server-side arrives as nil. `forceLoad()` then runs `meetingUrl = ...meetingUrl ?? meetingUrl`, which keeps the old text, and re-baselines to it on the next line. Opening Expert Settings while the cached profile is stale, or pulling it to refresh (`.refreshable { await viewModel.reload() }`), therefore shows a link the server no longer holds and treats it as saved.

The fix is iOS-only and small. Send "" when the baseline held a link and the trimmed field is now empty. Keep sending nothing when the baseline was already empty. Delete the stale comment. On a load, take the server's link and read a nil as "", for the field and so for its baseline. Each rule becomes a static function with explicit inputs. A tracer row sends its clear body through the API and checks the wire bytes, and pure rows table every case of both rules. No row builds the view model, so none depends on `UserManager.shared`. Also record the production check, the device re-test and an Android follow-up. There is no backend change and no Android change.

Requirement note: no SIGN or SET requirement names the meeting link. The gap is listed under SET-01 because VERIFICATION's requirements table groups truth 16 with SET-01, and both are the "Profile Settings saves that stick" truth. SET-01 stays reopened until this plan, and the item 22 device re-tests, pass.

Purpose: a link the expert clears is really cleared, the checkmark only shows when the change reached the server, and the screen never shows a link the server no longer holds.
Output: the fixed body builder and its pure rule, the fixed reload and its pure rule, one tracer row plus two pure suites, the CR-01 device re-test, an Android todo, and STATE.md notes.
</objective>

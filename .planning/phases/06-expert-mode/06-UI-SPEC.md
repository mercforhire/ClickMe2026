# Phase 06 — UI Design Contract

> Visual and interaction contract for Phase 06: Expert Mode. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **Scope of this contract.** Phase 06 is a bug-fix phase on a live SwiftUI app. It adds no palette, no spacing scale and no redesign. It locks (1) the design system exactly as the code has it today, inherited from `02-UI-SPEC.md` to `05-UI-SPEC.md`, and (2) the new or changed states, copy and interaction rules the 16 Phase 06 requirements (EXP-01 to EXP-10, EXP-12, EXP-14 to EXP-18) and the 20 `06-CONTEXT.md` decisions need: a delete confirmation and decimal pricing on the topic editor, a Cancel that reverts and a picker that can always show the stored time on Availability, the orphaned Booking Confirmed screen wired in after Accept, readable expired request cards, a private note with a 5,000 character cap, discard prompt and counter, no online dot on the expert hub, and a booking ID on the expert Booking Summary.
>
> **Key finding that changes the work, read before planning.** The iOS half of the currency picker (D-01 to D-04, EXP-03, EXP-17) is already in the code. Commit `73e729e` (2026-11-10, on `main`) shipped the CAD | USD segmented control, the paid-topic lock with its caption, the exact USD conversion-fee notice, the default from `pricing_limits.min_session_amount.default_currency` (else CAD), and the topic-own-currency seed on edit. `TopicEditorViewModel.swift` and `TopicEditorView.swift` at HEAD `dfa8456` carry it. `06-CONTEXT.md` (and the inventory rows E2, E3 it cites) describes the pre-`73e729e` code. **For iOS, D-01 to D-04 are therefore a preserve-and-verify contract, not a build.** What is still broken on iOS is the decimal price (D-05 / EXP-02: `Int(trimmedRate)`, `rateMajor * 100`, `.numberPad` has no decimal key) and the live minimum check, which parses whole units too. The Android half of EXP-17 is genuinely new (Android shows a read-only ISO badge and no picker today).
>
> **Every copy string in the Copywriting Contract is exact.** Executors must not paraphrase. Where a string comes from a decision, the decision id is cited; where it comes from Android, the Android key is cited; where it already ships, the file is cited. Money in copy is shown as `CA$12.50` for illustration; any real amount comes from the shared `Money` formatter (Phase 2 D-09, `ClickMe2026/Utils/Money.swift`).
>
> **Live-data warning.** Every environment points at the production backend with live Stripe keys. Accept and Decline on a request change a real booking and a real card hold. Device checks use test accounts and a free topic wherever the check does not need money (see "Device-only checks").
>
> **Cross-repo.** EXP-17 and EXP-18 also change `../ClickMe_Android` (one commit per repo). The Android half is specified in "Android parity contract". No backend change is expected.

New or changed layout, in full:

1. **Booking Note counter.** A single text line directly under the editor card, trailing-aligned, 4 pt (xs) below it, inside the existing 20 pt horizontal screen padding. Shown only from 4,500 characters. Reserves no space before that, so the editor does not jump.
2. **Booking Summary ID line.** One `Text` added as the last child of the client-header `VStack` (`ExpertBookingSummaryView.clientHeader`). That stack's `spacing` moves from 5 to **4 (xs)**, because the stack is being edited and 5 is off the declared scale. The View Profile link and the new ID line then sit 4 pt apart.
3. **Booking Note custom back button.** A 44 x 44 pt hit frame (`.frame(width: 44, height: 44)` with `.contentShape(Rectangle())`), the minimum touch target.
4. **Time-range picker inserted row.** Same 44 pt row height and full-width tap area as every other row. No new spacing.
5. **Expired request card.** No spacing change. Only fill, border and opacity change (see Color).
6. **Booking Confirmed.** No spacing change. The wired-in screen keeps its shipped vertical rhythm.

Exceptions declared for new Phase 06 layout: none. Every new interactive control is at least 44 pt: the custom back button (44 x 44), the inserted picker row (44), the Delete and discard dialogs (system alert buttons), and the Confirmed capsules (52, unchanged).

### Generic-label waiver

Rule: every new Phase 06 call-to-action label is a specific verb plus noun where one exists (`Add to Calendar`, `Back to Home`, `Keep editing`). Generic labels are **waived, with the reason below**, for exactly the controls in this table, and for no new control. | Label | Where | Reason for the waiver |
|-------|-------|-----------------------|
| `Cancel` (cancel role) | Delete-topic prompt (new), time-range sheet, Accept sheet, topic editor (shipped) | Established iOS convention for backing out of a confirmation, the same word D-14 specifies. Android's `Keep Topic` is a text-only difference the user's D-14 chose not to adopt |
| `Delete` (destructive role) | Delete-topic prompt (new) | The prompt title `Delete this topic?` and its message supply the noun. A system destructive button names its verb |

| `OK` (cancel role) | Error alerts on the topic editor, Request Decision, Booking Note, Availability (shipped) | System alert acknowledge. The title and message carry the meaning |
| `Save`, `Done`, `Confirm` | Toolbar and sheet buttons (shipped) | Single-purpose screens or sheets titled for their object (`My Note`, `Select Time Range`, `Confirm Booking`). Existing labels, unchanged |
| `Accept` | Request Decision footer capsule (shipped) | Paired with `Decline` on a screen whose whole subject is one booking request; same word as Android. Existing label, unchanged |

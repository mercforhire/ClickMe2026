<objective>
CHAT-05, CHAT-06 and the client half of CHAT-07: when a chat opens it knows who the other person is straight away (D-10), loading older messages never duplicates any (D-11), and read receipts go out for every page the user loads, even when the socket was still connecting (D-16).

Purpose: today the peer id is guessed from the first peer message (so a new thread has no View Profile and no typing indicator), `loadEarlier` prepends the page with no filter, and the read receipt for page 1 is lost when the chat opens before the socket connects, so the unread badge never clears.

Output: `ChatThreadLookup` (one scan used here and by plans 07-04 and 07-05), `refreshThreadInfo()` / `viewDidAppear()` on the view model, `loadEarlier` through the reducer, per-page read receipts held until connected, `RealtimeService.isConnected` and `onConnect`, and two stubbed test suites.
</objective>

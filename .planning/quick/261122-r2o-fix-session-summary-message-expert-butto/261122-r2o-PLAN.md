<objective>
Fix the client Session Summary "Message Expert" button, which does nothing in App Store build 6 because `BookingSummaryView` defaults its message closure to an empty one and no caller passes it.

The screen now opens the chat itself: the view model gets or creates the thread with the booking's expert through `POST /chats/initiate`, and the view hands the thread to the shell's `openChatThread` action, so all three entry points work with no call-site change. A failure raises an alert instead of being swallowed, and a second tap while the request runs is ignored.

Purpose: a client who wants to follow up with an expert after a past or cancelled session can reach them in one tap. iOS only, no backend change, so the backend freeze is unaffected. The fix ships in build 1.1 (7).
Output: the fixed view model, view and action subview, six unit tests, one R7 device-check step in the regression checklist, one code commit and one docs commit (not pushed).
</objective>
